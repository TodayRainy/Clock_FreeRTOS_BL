# Clock F407 Workflow

## 项目选择

默认主线为 `BL_W25Q_AB_VSCode/`。

`BL/`、`Boot2026/`、`BL_W25Q_AB/` 和 `STM32F4_WT_FreeRTOS/`
默认作为历史或参考项目。用户明确指定某个目录时，以用户选择为准。

IDE 当前打开的文件不自动决定修改目标。

默认使用 Windows 原生开发环境。除非用户重新提出要求，否则不引入 WSL 或 Ubuntu 配置。

## Skill 路由

根据任务只选择必要的 Skill，不要机械调用全部工具：

- CMake、Ninja、ARM GCC 构建和固件空间分析：使用 `$gcc`。
- J-Link 连接、烧录、复位、内存检查和在线调试：使用 `$jlink`。
- UART、COM 口、升级协议和日志观察：使用 `$serial`。
- Keil 历史工程构建或配置检查：使用 `$keil`。
- FreeRTOS 任务、同步、调度和中断问题：使用
  `$stm32-freertos-developer`，但应先识别项目当前使用 HAL 还是 SPL。
- 用户明确要求嵌入式代码审查时：使用 `$embedded-review`。
- 用户明确要求串联构建、烧录、调试和观察时：使用 `$workflow`。

除非用户明确选择对应后端，否则不要优先使用：

- `$stm32-debug`
- `$openocd`
- `$probe-rs`
- `$eide`

这些 Skill 的默认目标、调试器或工作环境可能与当前工程不同。

## 动态项目状态

开始任务时读取当前代码、CMake 配置和相关项目文档，不把 Skill 中的描述当作硬件或
协议事实。

Flash 布局、波特率、存储映射、固件格式、签名方案、状态机、工具路径和测试参数都
以当前代码和用户本次目标为准。用户可以有意修改或优化这些内容。

不要因为历史报告记录了某个参数，就阻止用户修改该参数；应分析影响范围、实施修改
并进行与风险相称的验证。

## 实板操作

为完成当前项目的开发和验证，允许主动使用 J-Link 和串口执行必要的烧录、升级、复位
及实板测试，不需要每次重新请求许可。

执行写入前必须确认板子具备可执行的救援路径，例如：

- J-Link/SWD 仍能正常连接；
- 存在可用的救援镜像，或能够重新构建并烧录 Bootloader 和应用；
- 本次操作不会关闭调试接口或启用不可逆的读写保护。

普通 Bootloader、Application 和 XBIN/A-B 升级均可在满足救援条件时执行。

如果操作涉及 RDP、WRP、Option Bytes、关闭 SWD、探针固件升级，或者现有救援条件
失效，应暂停并向用户说明风险。

烧录后应验证设备仍可连接，并报告写入内容和最终运行状态。
